# CITS-to-go

**CITS-to-go** is a portable C-ITS capture bridge built around a Seeed Studio XIAO ESP32-C5 and an Android phone.

The ESP32-C5 firmware listens for C-ITS packets, forwards them over USB serial and optionally over GPIO SPI to a Wi-Fi uplink board, and the Android app can save the captured USB data as PCAP and forward the packets to an MQTT broker using the same packet-topic style as the original OpenTrafficMap receiver firmware.

## Project status

This project is experimental.

Currently implemented goals:

- Capture C-ITS packets with a Seeed Studio XIAO ESP32-C5.
- Blink the onboard USER LED when messages are received.
- Stream captured packets to an Android phone over USB-C.
- Optionally mirror captured packets to another device over GPIO SPI.
- Save captures as PCAP files on Android.
- Forward packets to MQTT.
- Keep compatibility with the OpenTrafficMap-style MQTT packet format.

## Required hardware

To build and use CITS-to-go, you need:

- **Android phone** with USB host / OTG support
- **Seeed Studio XIAO ESP32-C5**
- **USB-C to USB-C cable**
- Optional: second microcontroller connected to the XIAO GPIO SPI pins
- Suitable antenna / RF setup for the intended C-ITS reception band (Already shipped with the XIAO ESP32-C5, but performance may be improved with a better antenna or external RF front-end)
- Optional: MQTT broker reachable from the Android phone

Notes:

- The Android phone provides power and USB serial connectivity to the XIAO ESP32-C5.
- Use a proper data-capable USB-C cable. Some USB-C cables are charge-only.
- Reception quality depends heavily on antenna choice, placement, and local C-ITS traffic availability.

## Software components

The project contains two main parts:

### ESP32-C5 firmware

The firmware runs on the Seeed Studio XIAO ESP32-C5.

Responsibilities:

- Configure the ESP32-C5 receiver path for C-ITS packet capture.
- Receive C-ITS packets.
- Blink the XIAO onboard USER LED on received/logged packets.
- Send captured packets to the Android app over USB serial.
- Optionally send the same packet frames over GPIO SPI to a Wi-Fi uplink board, defaulting to D1/GPIO0 CS, D2/GPIO25 READY, D3/GPIO7 MOSI, D4/GPIO23 MISO, and D5/GPIO24 SCLK.

### ESP32-C5 Wi-Fi uplink firmware

The optional `wifi-uplink-firmware/` project runs on a second XIAO ESP32-C5. It receives the capture board's CTG1 frames over GPIO SPI and publishes the raw packet payloads directly to MQTT over Wi-Fi.

### Android app

The Android app runs on the phone connected to the XIAO ESP32-C5.

Responsibilities:

- Read the USB serial stream from the ESP32-C5.
- Decode C-ITS packet frames.
- Decode the firmware's USB serial packet frames.
- Save captures to PCAP.
- Forward packets to MQTT.

## MQTT format

CITS-to-go is intended to use the same packet-publishing style as the original OpenTrafficMap firmware.

Packet messages are published as raw binary packet payloads:

```text
Topic:   its/<nodeid>/packet
Payload: raw binary packet bytes
QoS:     0 by default
Retain:  false
```

## Troubleshooting

### Android asks for USB permission repeatedly

Try:

- Reconnecting the XIAO.
- Using a different USB-C data cable.
- Checking that the phone supports USB host / OTG mode.
- Reopening the app after granting permission.

### No packets appear

Check:

- The firmware is flashed and running.
- The phone has USB permission.
- The foreground service is active.
- The XIAO USER LED blinks when packets are received.
- There is C-ITS traffic nearby.

### MQTT says `broken pipe`

The current app should treat this as a reconnectable network failure:

- The MQTT socket is closed.
- Packets remain in the retry spool.
- The app reconnects with backoff.
- Publishing resumes from the spool.

If it still happens repeatedly:

- Disable battery optimization for the app.
- Keep the foreground notification active.
- Check mobile/Wi-Fi connectivity.
- Check broker keepalive/firewall settings.

## Safety, privacy, and legal notes

C-ITS messages may contain sensitive operational or location-related data.

Before capturing, storing, forwarding, or publishing packets:

- Check the rules in your jurisdiction.
- Avoid publishing raw captures that could identify vehicles, infrastructure, routes, or individuals.
- Treat PCAP files as potentially sensitive data.
- Do not use this project for unlawful monitoring or interference.
- This project is receive/logging oriented and must not be used to transmit unauthorized messages.
